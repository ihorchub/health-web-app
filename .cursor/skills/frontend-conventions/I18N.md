# i18n (EN / UK)

## Library

`react-i18next` with **manual** locale files. No machine translation.

## What switches with language

| Kind | Behaviour |
|------|-----------|
| UI chrome (buttons, titles, empty states, errors) | `t('namespace:key')` from UK/EN JSON |
| Platform catalogs (specialty labels, statuses, curated cities) | Localized via i18n and/or API locale |
| User-entered data (name, free-text reason, review body) | **As typed** — does not change when toggling UK/EN |
| Doctor bio / long platform content | Dual fields on backend when authored; show active locale with fallback to the other — no auto-translate |

## File layout

```
src/i18n/
  locales/
    uk/
      common.json
      auth.json
      search.json
      booking.json
      patientRoom.json
      doctorDay.json
      profile.json
      workingHours.json
    en/
      (same namespaces)
  index.ts
```

Default language: **uk**. Persist user choice. Send the same locale to API (`Accept-Language` or agreed param) for localized **content**.

## Rules

- No raw user-facing strings in JSX — use keys
- Author both `uk` and `en` yourself (or leave EN empty only with explicit fallback policy)
- Namespaces by area/SCR — do not dump everything into one file
